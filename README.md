# 💼 Business Dashboard

Система управления бизнесом с одним видом сырья и одним готовым продуктом: продажи, частичные оплаты, расходы, производство, склад, себестоимость и точка безубыточности.

**Хостинг:** GitHub Pages | **База данных:** Supabase | **Валюта:** TJS (сомони)

---

## 🚀 Быстрый старт

### 1. Создать проект в Supabase

1. Зайди на [supabase.com](https://supabase.com) → **New Project**
2. Дай имя проекту (например, `business-dashboard`)
3. Дождись инициализации (~2 минуты)
4. Открой **SQL Editor → New query**
5. Вставь целиком единственный файл `supabase/FULL_SETUP_NEW_PROJECT.sql` и нажми **Run** один раз
6. Убедись, что SQL Editor показал **Success**, затем перейди в **Settings → API** и скопируй:
   - `Project URL` → это твой `VITE_SUPABASE_URL`
   - `anon public` key → это твой `VITE_SUPABASE_ANON_KEY`

### 2. Настроить локальный запуск

```bash
npm install
```

Отредактируй `.env.local`:
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

```bash
npm run dev
```

Открой: http://localhost:5173/

> В папке `supabase` оставлен один актуальный файл — `FULL_SETUP_NEW_PROJECT.sql`. Он рассчитан на один запуск в новой пустой Supabase.

## Как устроен учёт

- Выручка признаётся в дату продажи, даже если клиент заплатил позже.
- Оплата учитывается в движении денег по фактической дате платежа; поддерживаются частичные оплаты и долг клиента.
- Закупка сырья увеличивает склад и уменьшает деньги, но не списывается сразу в прибыль.
- Сырьё и готовый продукт оцениваются по средневзвешенной себестоимости.
- Переменные производственные расходы включаются в стоимость произведённого товара и списываются через себестоимость проданного.
- Переменные расходы на продажу (доставка клиенту, комиссия) списываются сразу в периоде и не увеличивают стоимость склада.
- Постоянные расходы списываются в том месяце, когда внесены.
- Личные изъятия уменьшают деньги, но не прибыль бизнеса.
- База запрещает отрицательные остатки, включая ошибки в датах прошлых операций.

Для исходных остатков обязательно укажи их стоимость в **Настройки → Начальные остатки**. Иначе количество будет правильным, но прибыль до ввода стоимости нельзя считать подтверждённой.

## 📦 Деплой на GitHub Pages

### 1. Создать репозиторий на GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/YOUR_USERNAME/business-dashboard.git
git push -u origin main
```

### 2. Добавить секреты в GitHub

**GitHub repo → Settings → Secrets and variables → Actions → New repository secret**

- `VITE_SUPABASE_URL` = твой Supabase URL
- `VITE_SUPABASE_ANON_KEY` = твой anon key

### 3. Включить GitHub Pages

**GitHub repo → Settings → Pages** → Source: **GitHub Actions**

Сайт будет доступен: `https://YOUR_USERNAME.github.io/business-dashboard/`

## 🔢 Формула точки безубыточности

```
Маржа на кг  = Цена продажи − Переменные затраты на кг
Точка 0 (кг) = Фиксированные расходы ÷ Маржа на кг
Цель (кг)    = (Фиксированные расходы + Желаемая прибыль) ÷ Маржа на кг
```

## 🛠️ Стек

- **Frontend:** Vite 5 + React 18 + TypeScript
- **Стили:** Tailwind CSS v3 (тёмная тема, glassmorphism)
- **БД / Auth:** Supabase (PostgreSQL)
- **Графики:** Recharts
- **Иконки:** Lucide React
- **Деплой:** GitHub Pages + GitHub Actions
- **Среда сборки:** Node.js 22

## Проверка перед публикацией

```bash
npm test
npm run lint
npm run build
```

Чек-лист:

1. Для новой Supabase выполнить `FULL_SETUP_NEW_PROJECT.sql` и получить сообщение **Success**.
2. Внести начальные остатки и их стоимость, цену продажи, плановый выход и переменную стоимость на кг.
3. Провести контрольный сценарий: закупка → производство → продажа → частичная оплата.
4. Сверить количество и стоимость склада, долг клиента, P&L и Cash Flow.
5. Добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в GitHub Secrets.
6. Выполнить команды проверки выше и только затем публиковать.

Полный контрольный сценарий с точными цифрами находится в [`TESTING.md`](./TESTING.md).
